# 模型层说明

> 本文档记录 PersonalRag **模型推理层**的实际情况：模型清单、部署位置、接口契约、调用方、配置项与运维方式。
> 最后更新：2026-11-04（端到端验证已通过）

## 一、当前架构

模型层已从本机迁移到 **AutoDL GPU 实例**，本机不再保存模型权重。三个推理服务独立部署，本机通过 SSH 端口转发透明访问，`config.yaml` 中的 `base_url` 保持 `localhost` 不变。

```
┌──────────── 本机（Windows） ────────────┐
│  API(:8000) / 前端(:5173) / Celery worker │
│         │                                │
│         │ HTTP（localhost，经 SSH 隧道）   │
└─────────┼────────────────────────────────┘
          │
   SSH 本地端口转发
   8001 → AutoDL:8001   (embedding)
   8002 → AutoDL:8002   (rerank)
   11434 → AutoDL:8000  (vLLM, OpenAI 兼容)
          │
┌─────────▼──── AutoDL（Linux GPU） ───────┐
│  FlagEmbedding FastAPI ×2   +   vLLM     │
└──────────────────────────────────────────┘
```

**关键点**：本机 `models/` 目录已清空，只保留本文档。任何模型推理请求都必须经由 AutoDL 返回，**实例未开机时检索与问答链路不可用**。

## 二、模型清单

| 层 | 模型 | 精度 | 权重体积 | 显存占用（估算） | 端口 |
|---|---|---|---|---|---|
| Embedding | BAAI/bge-m3 | fp16 | ~2.2GB | ~1.2GB | 8001 |
| Rerank | BAAI/bge-reranker-base | fp16 | ~2.1GB | ~0.6GB | 8002 |
| LLM | Qwen3-30B-A3B-Instruct-2507-AWQ | AWQ-4bit (compressed-tensors) | ~16.85GB | ~18.3GB（权重+KV） | 8000 |

LLM 为 **MoE 架构**：128 个专家、每 token 激活 8 个（总参 30B / 激活 3B），原生上下文 256K（本项目限 8192 使用）。

**24GB 显卡显存预算**：vLLM 19.2G（`--gpu-memory-utilization 0.8` 硬限）+ embedding 1.2G + rerank 0.6G ≈ **21G**，需观察实际峰值。

### vLLM 启动参数

```bash
vllm serve /root/autodl-tmp/personalrag/models/Qwen3-30B-A3B-Instruct-2507-AWQ \
    --served-model-name Qwen3-30B-A3B-Instruct-2507 \
    --host 127.0.0.1 --port 8000 \
    --max-model-len 8192 \
    --gpu-memory-utilization 0.8 \
    --max-num-seqs 8
```

| 参数 | 说明 |
|---|---|
| `--served-model-name` | 必须与 `config.yaml` 的 `llm.model` 完全一致 |
| `--max-model-len 8192` | 与 `config.yaml` 的 `context_window: 8192` 对齐 |
| `--gpu-memory-utilization 0.8` | 显存硬上限 ~19.2G，给两个 bge 服务留余量 |
| `--max-num-seqs 8` | 压低并发与 KV 峰值 |
| 量化 | compressed-tensors 格式，vLLM **自动识别**，无需加 `--quantization` |

### Embedding / Rerank 服务

基于项目内 `model_services/serve_*.py`（FlagEmbedding），与 AutoDL 环境变量对接：

## 四、接口契约

客户端代码位于 [app/clients/model_services.py](file:///d:/ProjectAll/trae_case/PersonalRag/app/clients/model_services.py)，入库侧另见 [app/ingest/embedder.py](file:///d:/ProjectAll/trae_case/PersonalRag/app/ingest/embedder.py)。

### 4.1 Embedding：`POST /v1/embeddings`

请求：

```json
{"texts": ["文本1", "文本2"]}
```

响应：

```json
{
  "dense": [[0.01, 0.02, ...], [ ... ]],
  "sparse": [{"12": 0.8, "345": 0.3}, { ... }]
}
```

- `dense`：1024 维稠密向量
- `sparse`：`{token_id字符串: 权重}` 的稀疏向量，供 Milvus 稀疏检索通道使用
- 在线查询向量带 Redis 缓存（key `query:emb:<md5>`，TTL `retrieve.cache.query_embedding_ttl=3600`）

### 4.2 Rerank：`POST /v1/rerank`

请求：

```json
{"query": "问题", "documents": ["文档1", "文档2"]}
```

响应：

```json
{"scores": [0.92, 0.35]}
```

客户端按 `models.rerank.batch_size`（默认 64）**分批请求后拼接**，不是一次性发送全量候选。

### 4.3 LLM：OpenAI 兼容 `/v1/chat/completions`

- 客户端：`openai.AsyncOpenAI`（`get_llm_client()`）
- 三种用法：`llm_chat`（非流式）、`llm_chat_stream`（流式）、`llm_json`（宽容解析 JSON，截取首 `{` 到末 `}`）
- `api_key="EMPTY"` 为占位符；vLLM 未启用 `--api-key` 时不校验该值

## 六、关键配置（config.yaml）

```yaml
models:
  embedding:
    base_url: http://localhost:8001      # → AutoDL:8001
    model: bge-m3
    dim: 1024
    batch_size: 16
    timeout: 120
  rerank:
    base_url: http://localhost:8002      # → AutoDL:8002
    model: bge-reranker-base
    batch_size: 64
    timeout: 120
  llm:
    base_url: http://localhost:11434/v1  # → AutoDL:8000
    model: Qwen3-30B-A3B-Instruct-2507   # 与 vLLM --served-model-name 一致
    temperature: 0.1
    max_output_tokens: 1024
    context_window: 8192                 # 与 vLLM --max-model-len 一致
    timeout: 180
```

检索相关（与模型层强耦合）：`retrieve.per_channel_top_k=100`、`fusion.vector_weight=0.3`、`rerank.score_threshold=0.05`、`rerank.top_n=5`、`rerank.candidate_pool_max=400`。

> **一致性要求**：`llm.context_window` ↔ vLLM `--max-model-len` ↔ `assemble.context_window` 三处必须同步调整。

## 七、运维手册

### 7.1 启动（有卡开机后）


脚本会：注入 fp16 与模型路径环境变量 → 检测端口是否已占用 → 依次 nohup 拉起 embedding / rerank / vLLM。vLLM 首次加载约需 1–3 分钟。

### 7.3 本机 SSH 隧道

**推荐**：`产物/AutoDL部署/autodl_tunnel.py`（paramiko 实现，密码内置，断线自动重连，已被 .gitignore 排除）：

```powershell
D:\Developers\Anaconda3\envs\personal_rag\python.exe 产物\AutoDL部署\autodl_tunnel.py
```

或原生 ssh（需手动输密码，断线不重连）：


#### 7.4 换实例（唯一需要的操作）

本机服务（API/Celery/前端/隧道）启动后常驻，平时无需任何脚本。**仅在 AutoDL 换了实例（SSH 端口/密码变化）时**运行：

```powershell
powershell -ExecutionPolicy Bypass -File 产物\AutoDL部署\换实例.ps1 -Port <新端口> -Pass '<新密码>'
```

流程：更新 `实例配置.json` → 停止旧隧道 → 远程拉起三服务（幂等）→ 启动新隧道 → 健康检查。隧道日志在 `产物/AutoDL部署/logs/本机/`。

## 八、Ollama 遗留逻辑清理（已完成）

模型层最初用 Ollama 托管 LLM，客户端中曾有一套约 150 行的 **Ollama 专用降级重试机制**：OOM 时改走 Ollama 原生 `/api/chat` 端点，按档位逐级下调 `num_gpu`（18→8→0）与 `num_ctx`（4096→2048）后重试。

迁移到 vLLM 后该机制已确认有害并删除：

| 问题 | 说明 |
|---|---|
| 运行期不会触发 | vLLM 启动时按 `--gpu-memory-utilization` 预分配显存，放不下会启动失败，不进该分支 |
| 触发即失败 | vLLM 无 `/api/chat` 端点，重试必然 404 |
| 永久污染进程 | `_remember_profile()` 会把 `_native_profile` 写成全局状态，后续所有请求固定走原生端点，只能重启进程恢复 |

**清理结果（2026-11-03）**：`app/clients/model_services.py` 由 253 行精简至 102 行，删除 `_DEGRADE_LADDER`、`_native_chat`、`_native_chat_stream`、`_TextCompletion`、`_is_oom_error` 等全部 Ollama 专属代码；`llm_chat` / `llm_chat_stream` 仅保留 OpenAI 兼容调用路径；`api_key` 由 `"ollama"` 改为 `"EMPTY"`（vLLM 未启用 `--api-key` 时的占位符）。

保留的公共接口（调用方无需改动）：`embed_texts`、`embed_query`、`rerank`、`get_llm_client`、`llm_chat`、`llm_chat_stream`、`llm_json`。

> 副作用：不稳定的 LLM 请求现在会直接抛出原始错误（不再有静默降档）。若需韧性，应在应用层用指数退避重试，见第十一章第 2 条。

## 九、本机回退方案

如需在本机（无 GPU）独立运行 embedding/rerank 作为应急：

```bash
pip install modelscope
python scripts/download_models.py          # 下载 bge-m3 + bge-reranker-base 到 models/
python model_services/serve_embedding.py   # :8001
python model_services/serve_rerank.py      # :8002
```

- 不加 `BGE_USE_FP16` 时走 CPU fp32（本项目历史上即此模式）
- 模型默认从项目根 `models/` 加载，可用 `BGE_M3_DIR` / `BGE_RERANKER_DIR` 覆盖
- LLM 回退需另有 OpenAI 兼容服务（Ollama 或本地 vLLM），并同步改回 `config.yaml` 的 `llm.model`
- 手动下载地址：ModelScope / HuggingFace 的 `BAAI/bge-m3`、`BAAI/bge-reranker-base`

## 十、已知限制

| 限制 | 说明 |
|---|---|
| 强依赖实例在线 | 本机已无模型权重，AutoDL 关机/端口变更时检索问答全链路不可用 |
| 端口会变 | AutoDL 实例重启后 SSH 端口与地址可能变化，需重新核对隧道参数 |
| 显存余量小 | 24G 卡上总占用约 21G，几乎无冗余；`max-num-seqs` 调高易 OOM |
| 上下文受限 | 模型原生 256K，但受 24G 显存约束限用 8192 |
| LLM 调用无重试 | Ollama 降档逻辑已删除（见第八章），网络抖动或超时会直接抛错，由调用方兜底 |
| 服务不持久 | 实例重启后需重新执行 `start_services.sh`（未配置开机自启） |

## 十一、可选的后续优化

1. **开机自启**：用 systemd unit 或 AutoDL 自定义启动脚本托管三个服务
2. **应用层重试**：用 tenacity 对 embedding/rerank/LLM 做指数退避重试与熔断（Ollama 降档分支已于 2026-11-03 删除）
3. **监控**：采集 vLLM 的 `/metrics`（Prometheus）与 TTFT/吞吐指标
4. **批量优化**：入库时把 embedding 的 `batch_size` 随 GPU 调大（当前 16 偏保守）
